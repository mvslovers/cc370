# libc370 corpus -- as370 against IFOX00 (#23)

A frozen snapshot of the libc370 assembler corpus, with IFOX00's own object
deck for every module. `make test-libcorpus` assembles each one with the
working tree's as370 and compares it with IFOX00's deck: every card before
END (the END card carries the translator IDR, which as370 does not
reproduce), and the deck sizes must agree. It needs nothing outside this
repository -- no libc370 checkout, no MVS -- and takes about 20 seconds.

This is the **oracle** guard. `make test-corpus` (`../corpus/`) is the
regression guard: it compares two as370 binaries over the live libc370 tree
and answers "did my change move anything", not "is as370 right".

## What is here

| | |
|---|---|
| `manifest.tsv` | every module as `Lnnnn`, its path under `src/`, its SHA-256; the header records where the snapshot came from |
| `src/` | 753 inputs: 29 hand-written assembler sources of libc370 and 724 `.s` files cc370 generated from libc370's C sources (`sdk/mklibc.py`) |
| `maclib/`, `sysmac/` | libc370's macro libraries, as the host searches them (`-I maclib -I sysmac`) |
| `ccmacros/` | cc370's `macros/` (PDPTOP, PDPPRLG, PDPEPIL) at the time of the snapshot |
| `ifox/Lnnnn.obj` | IFOX00's deck per module |
| `ifox/rc.tsv` | IFOX00's condition code per module, with the job that produced it |
| `ifox/stamps.tsv` | the `&SYSDATE`/`&SYSTIME` IFOX00 stamped into three decks; `check.sh` gives as370 the same through `ASMDATE`/`ASMTIME` |
| `ifox/excluded.tsv` | decks not used as an oracle, with the reason |

The inputs are frozen because they do not hold still. The generated `.s`
exist in no repository, and they change whenever libc370's C sources or the
cc370 on PATH changes. They were regenerated by another session at 13:45
on the day of the snapshot, half an hour before it was copied (14:19).

## How the decks were produced

`../oracle/capture_libcorpus.py --submit`, on MVSTK5-REF (the pinned oracle),
2026-10-04, between snapshots `MVSTK5-REF-20261004-1432` and `-1500` (2,789
members, unchanged):

- The three macro libraries were created as PDSs and every member written
  **binary**, converted on the host exactly as as370 reads a source: valid
  UTF-8 as UTF-8, otherwise Latin-1, then CP037. Python's `cp037` equals
  as370's table on all 191 printable Latin-1 characters. Each member was read
  back and compared. Nine sysmac members carry non-ASCII characters (`¬`,
  and a UTF-8 `³` in `getmain`).
- The modules were assembled in 18 jobs (JOB00324-JOB00341), each source
  in-stream as `capture.py` sends it, `PARM='DECK,LIST,NOLOAD,XREF(FULL),RENT'`,
  SYSLIB = the three libraries in the host's order, SYSPRINT DUMMY, SYSPUNCH
  appended to one data set per job.
- Each job's data set was read back binary and cut at the END cards. A cut
  deck was accepted only if its ESD names equalled as370's for that module.
  All 753 were.
- Everything created on the oracle was deleted afterwards.

The inputs are pure ASCII. Only `|` (8 files), `!` and `[ ]` (one each) go
through mvsMF's in-stream text conversion beyond the alphanumerics, and
those modules are byte-identical too.

## Renewing the snapshot

A deliberate act, not something to do on every libc370 change:

1. regenerate libc370's `.s` (`sdk/mklibc.py`), copy the inputs and macro
   libraries here and rewrite `manifest.tsv` (member names must stay
   `Lnnnn`, in manifest order);
2. take an MVSTK5-REF snapshot, run
   `AS370_MVS_ENV=.env python3 as370/tests/oracle/capture_libcorpus.py --submit`,
   take the second snapshot and compare;
3. rebuild `ifox/rc.tsv`, `ifox/stamps.tsv` (any module whose deck carries
   `&SYSDATE`/`&SYSTIME`) and `ifox/excluded.tsv`, and run `make test-libcorpus`.
