=head1 NAME

ld370 - host-native MVS linker (IEWL replacement) + host-to-MVS transport

=head1 SYNOPSIS

B<ld370> [B<-v>] B<-o> I<out> [B<-L> I<dir> B<-l> I<name>] [B<--include> I<name>]
[B<--entry> I<name>] [B<--alias> I<name>]... [B<-xmit>] [B<-iebcopy>] [B<--dsn> I<ds>] [B<--name> I<n>] [B<--blocksize> I<n>]
[B<--ac> I<n>] [B<--rent>|B<--norent>] [B<--reus>|B<--noreus>] [B<--refr>]
[B<--sparse-text>] [B<--map> I<file> [B<--xref>]] I<obj>...

B<ld370> B<--pack> I<member> [I<member> ...] B<-o> I<out> [B<-xmit>] [B<-iebcopy>] [B<--dsn> I<ds>]

=head1 DESCRIPTION

B<ld370> links one or more OS/360 object decks into an MVS load module on the
host, replacing the mainframe linkage editor (B<IEWL>); the member it produces is
byte-identical to IEWL's. It performs automatic library call against B<.a>
archives (see L<ar370(1)>), and can additionally wrap the result for transport to
MVS: an IEBCOPY unloaded-PDS image (B<-iebcopy>) and a TSO TRANSMIT / NETDATA file
(B<-xmit>, RECFM=FB80) that uploads cleanly and installs with C<RECV370>.

It is invoked automatically by L<cc370(1)> for the link/transport stages.

=head1 OPTIONS

=over 4

=item B<-o> I<out>

The load-module member to write (defaults to F<a.out>). This member is always
written; the transport wrappers below are B<additive> and never replace it.

=item B<-e>, B<--entry> I<name>

Set the module entry point. With B<--pack>, the entry of each bare member
(see there).

=item B<--alias> I<name>

Give the member an alias, as the IEWL C<ALIAS> statement does; repeatable. Each
alias is a second directory entry in the B<-iebcopy>/B<-xmit> output, pointing
at the member's data, with the alias bit and the member's name and entry point in
its user data. Its own entry point follows IEWL's rule: an alias that names an
external symbol of the module enters at that symbol, any other alias where the
member does. So an alias spelled like an entry inside the module does B<not>
start the program at its main entry. A name may appear once in a library, member
or alias; a clash is refused. Aliases need a directory, so a bare B<-o> member
carries none (warned). B<--pack> keeps the aliases of a B<-iebcopy> input, and a
C<NAME=> rename re-points them at the new name; B<--alias> itself is refused with
B<--pack>.

=item B<-l> I<name>, B<-L> I<dir>

Auto-call the archive C<lib>I<name>C<.a>, searching directory I<dir>. Unresolved
strong external references fail the link unless B<--allow-unresolved> is given.

=item B<--include> I<name>

Force-include an archive member even if nothing references it.

=item B<--map> I<file>

Write a text load map to I<file> (C<-> = standard output) after the member is
written: every section in origin order with its type (SD, PC, CM), origin,
length and the input it came from --- the object path as given, or
I<archive>C<(>I<member>C<)> followed by C<include> or C<autocall> --- with the
entries it defines indented beneath it, and any unresolved names at the end.
The map carries no clock and no page headers, so the maps of two links compare
with B<diff>. It does not change the member. Refused with B<--pack>, which
places no sections.

=item B<--xref>

Add the cross-reference to the B<--map> output (refused without it): under
each section, every address constant that names an external symbol or a
common section --- its
offset in the section, the constant type (A, V), the symbol, and the address
and section it resolved to, or C<unresolved>. A reference to an entry inside
an unnamed private-code section names that section by its origin
(C<in PC> I<origin>). It does not change the member.

=item B<-iebcopy>

Also write the IEBCOPY unloaded-PDS image to I<out>F<.iebcopy>.

=item B<-xmit>

Also write a TSO TRANSMIT (NETDATA) file to I<out>F<.xmit>.

=item B<--dsn> I<ds>

Name the target dataset recorded in the XMIT (default F<IBMUSER.HOST.LOAD>).

=item B<--name> I<n>

Set the PDS member name (otherwise derived from I<out>'s basename, extension
dropped, uppercased). Where the name reaches a directory or the map -- with
B<-xmit>, B<-iebcopy> or B<--map> -- it must be a valid MVS member name (1-8
characters, a letter or C<@#$> first, then letters, digits or C<@#$>); anything
else is refused with RC=2, never cut. A bare B<-o> member carries no name and is
not held to it.

=item B<--blocksize> I<n>

Set the target load-library B<BLKSIZE> (default B<15040>, the de-facto LINKLIB
blocksize on MVS 3.8j). It drives the text-record split limit, the unloaded-form
blocksize, the COPYR1 C<UBLKSIZE> and the INMR02 C<INMBLKSZ>, so a member built at
I<n> installs into any LINKLIB whose BLKSIZE is E<gt>= I<n>. The default 15040 fits
both 15040 and 19069 libraries. Use B<6144> for a small or older device, B<19069> for a 3350-full-track
library. B<Use the same value when building a module and when> B<--pack>-ing it:
B<--pack> does not re-split, so packing a member built at a larger blocksize while
declaring a smaller one is refused (the oversized blocks would not fit the target).
Range 1024..32740; a value that is not a number is refused.

=item B<--ac> I<n>

Set the APF authorization code (C<SETCODE AC(>I<n>C<)>) in the PDS2 directory
entry. Default 0, range 0..255 (it is one byte; a larger value is refused).
Applied to the freshly linked module; a B<--pack> of a B<-iebcopy> member keeps
that member's own AC.

=item B<--rent>, B<--reus>, B<--refr>

Mark the module reentrant, serially reusable or refreshable. B<A module is linked
with none of them unless asked>, as IEWL does (a plain IEWL link lists ATTR
C<03F2>); until cc370 1.2.0 every module was marked RENT and REUS. Declare what
the module is: a module with modifiable storage must not be marked reentrant.
B<--rent> and B<--reus> set C<PDS2ATR1>, B<--refr> sets C<PDS2ATR2>. Like B<--ac>,
they apply to the module being linked; a B<--pack> of a B<-iebcopy> member keeps
that member's own attributes (set when it was built), so per-member attributes mix
in one library.

=item B<--norent>, B<--noreus>

Accepted for scripts written against the old default, and since that default is
gone they change nothing on their own. Given together with the matching set-flag
they are refused.

=item B<--sparse-text>

Omit text records that no TXT card covered, so a C<DS> reservation is left
unwritten in the member instead of being carried as zeros. B<Off by default>, and
the default is the conservative one.

The predicate is B<definedness, never the byte value>. C<DC X'00'> is text a
programmer wrote and it stays; only a range nothing ever defined is dropped. The
object deck carries that distinction -- a C<DS> gap is the I<absence> of a TXT
card, C<DC X'00'> is a TXT card of zeros -- and ld370 keeps it through the link.
A record is dropped only if the whole record is undefined, so a reservation whose
ends share a record with real text keeps those records.

Two things to know before turning it on.

It costs byte-fidelity to IEWL, which does write such records: 33 of them across
the 5,230-member C<SYS1.AOS*> corpus, one of them a whole member's text. The
default keeps ld370 byte-faithful to the linker it is checked against; this flag
does not.

It relies on program fetch supplying zeros for a record that is not there. That
was measured on MVS 3.8j and it held, twice and with independent apparatus -- but
both runs were batch steps on one system with storage to spare. Fragmentation, a
long-running address space, other subpools, and a module large enough to take a
different allocation path are B<unmeasured>. Any C program depends on this
holding wherever it runs, because C requires static storage to start at zero.

Both measurements, and what they did not cover, are in F<internals/measurements/>.

=item B<--rent>, B<--reus>, B<--refr>

Set the PDS2 attributes, where B<--norent> / B<--noreus> clear them. B<--refr>
marks the module refreshable.

B<REFR lives in PDS2ATR2, not PDS2ATR1> -- it is the low bit of the second
attribute byte. This is worth stating because getting it wrong is silent rather
than visible: C<0x01> of ATR1 is C<PDS21BLK>, which the template already sets, so
a B<--refr> written against the first byte would change nothing and still look
implemented.

The bit position is measured against IEWL itself rather than against our own
decoder. One assembly, three IEWL links differing only in C<PARM>, read back with
C<IEHLIST LISTPDS FORMAT> on MVS 3.8j:

    PARM='NCAL,LIST,XREF'          ATTR 03F2
    PARM='NCAL,LIST,XREF,REFR'     ATTR 03F3
    PARM='NCAL,LIST,RENT,REFR'     ATTR C3F3

and IEHLIST's own attribute index names bit 15 C<REFR>. ld370's default
reproduces the first of those and B<--refr> the second, listed by the same
utility.

The set-flags are B<orthogonal>: each does exactly what it names. RENT implies
REUS as an attribute, but B<--rent> does not set REUS on the caller's behalf --
pass both for IEWL's C<RENT>.

Giving a set and a clear for the same attribute is B<refused>, not resolved by
precedence: either resolution would be a guess at what was meant.

Like B<--ac>, these apply to the module being linked and reach the B<directory
entry>, so they are visible only in the B<-iebcopy> / B<-xmit> form -- a bare
B<-o> member is byte-identical with and without them. A B<--pack> of a
B<-iebcopy> member keeps that member's own attributes.

=item B<--pack> I<member> [I<member> ...]

Pack one or more B<pre-built> members into the transport image(s)
I<out>F<.xmit> / I<out>F<.iebcopy> without linking --- one member, or several to
build a multi-member library. It defaults to B<-xmit> when neither B<-xmit> nor
B<-iebcopy> is given.

Each I<member> may be a bare load module (e.g. F<.lm>) or a single-member
B<-iebcopy> image. A bare member carries no PDS2 directory metadata: the module
length and the entry point are taken from its CESD, but the APF authorization
code (B<AC>) and the B<RENT>/B<REUS>/B<REFR>/... attributes live only in the
directory and cannot be recovered. A single-member B<-iebcopy> is
B<self-describing>: its whole directory entry is carried through (only the
relocated text TTR is re-stamped), so the entry point, length, AC and attributes
all survive. B<Pack any member that needs a non-zero AC or non-default
attributes from its> B<-iebcopy>, not its bare F<.lm>.

B<--ac>, B<--rent>, B<--reus> and B<--refr> on the B<--pack> command apply to a
bare member, so an authorized module can be packed from one by repeating the
flag. The B<entry point> of a bare member is the address of B<--entry> I<name>
in its CESD, or of C<@@CRT0> when no B<--entry> is given; a name the CESD does
not hold, or holds twice, is refused with RC=1. A member without C<@@CRT0> (a
plain assembler module) is packed at entry B<0>. Packing a bare member warns,
naming the entry, where it came from, and the attributes actually applied;
packing its B<-iebcopy> is silent, because nothing is lost, and B<--entry> does
not apply to it.

A member's name comes from its F<.iebcopy> directory, or (for a bare member) the
file's basename with the extension stripped and uppercased. Override either with
I<NAME>=I<FILE>; a bare member whose basename is not a valid MVS member name
B<must> be named this way, and B<--name> is refused with B<--pack> for that
reason. An XMIT, an archive or an object deck given as a member is refused, naming
what it is. B<--sparse-text> and B<--allow-unresolved> shape a link and are
ignored by a pack, with a warning; B<--map> and B<--alias> are refused.

=item B<-v>, B<--verbose>

Verbose: trace the link / pack phases on stderr.

=item B<--help>, B<-h>

Print the usage and exit.

=item B<--version>, B<-V>

Print the toolchain version and the commit it was built from, and exit.

=back

An argument beginning with B<-> that is not an option is refused (it used to be
taken as an input file), as is an option given last without its value.

=head1 INPUT

Every input that is not an archive (F<.a>, B<-l>) must be an OS/360 object deck:
80-byte cards, each beginning C<X'02'>, with an END card. Anything else -- a C
source, an XMIT, an archive without its F<.a> -- is refused with RC=1, and no
member is written.

A CSECT that an earlier object already defined is dropped with its text, space,
relocations and entries, and every reference binds to the first definition, as
IEWL does. IEWL says nothing; ld370 prints a note naming the CSECT, and the
return code is unchanged.

A common section (ESD type CM, from the assembler's C<COM>) is one area per
name for the whole link, as long as the longest contribution. Common sections
follow every object, each on a doubleword, in the order their names first
appear; they carry no text but count in the module length. That is IEWL's
layout.

Pseudo registers (ESD type XD from C<DXD> or a Q-type constant, and the
Q-type and C<CXD> relocations) are not handled yet: they stay unresolved
(cc370#76).

=head1 EXIT STATUS

=over 4

=item B<0>

The output was written. Warnings and notes do not change it.

=item B<1>

The link failed: an input could not be read or is not an object deck,
references stayed unresolved (without B<--allow-unresolved>), the B<--entry>
symbol was not found, or an output could not be written.

=item B<2>

A usage error: an unknown option, an option without its value, a value out of
range or not a number, an invalid member or alias name, or options that cannot be
combined.

=back

=head1 ENVIRONMENT

Every linked member carries a linkage-editor B<IDR> identification record
stamping the product, its version/modification level, and the date and time of
the link (the B<BIND> date, as displayed by tools that read the IDR). The date
and time are taken from the host clock, so two otherwise identical links are
B<not> byte-identical. The following variables override the clock, which is what
makes a link reproducible --- required whenever the output is byte-compared, as
F<ld370/tests/run.sh> does:

=over 4

=item B<LDDATE>=I<YYDDD>

The link date as a 5-digit Julian date: 2-digit year plus day-of-year 001..366.
For example C<26223> is 2026-08-11. Rejected with RC=2 if malformed.

=item B<LDTIME>=I<HHMMSS>

The link time as 6 digits, 24-hour. For example C<220517> is 22:05:17. Rejected
with RC=2 if malformed.

=back

Both are read independently: setting only one pins that field and leaves the
other on the host clock. They set the transmission's C<INMFTIME> in a B<-xmit>
file too, so an XMIT is reproducible as well. Its other INMR01 fields are fixed:
C<INMFNODE> C<ORIGNODE>, C<INMFUID> C<IBMUSER>, C<INMTNODE> C<IBMUSER> and
C<INMTUID> C<DUMMY> -- the values of the TSO TRANSMIT the format was matched
against (F<ld370/tests/fixtures/e2e.iewl.xmit>). RECEIVE and RECV370 install the
transmission whatever they say.
