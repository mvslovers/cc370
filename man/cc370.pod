=head1 NAME

cc370 - C cross-compiler driver for MVS 3.8j (System/370)

=head1 SYNOPSIS

B<cc370> [I<options>] I<file>...

=head1 DESCRIPTION

B<cc370> is the driver of a host-native cross-toolchain that compiles C to IBM
System/370 code for MVS 3.8j (TK4-, TK5, MVS/CE). It runs on the host
(macOS / Linux) and orchestrates the compiler proper (F<cc1>), the assembler
(L<as370(1)>) and the linker (L<ld370(1)>), so the only artifact that reaches the
mainframe is the finished load module.

It is a fork of GCC 3.4.6 for the C<cc370> target (an alias for the
C<i370-ibm-mvspdp> backend) and accepts the usual GCC-style options. B<-S> /
B<-c> set how far the pipeline runs, as in any GCC driver; by default it links a
finished MVS load-module member. B<-flinker-output=>I<type> additionally emits a
host-to-MVS transport wrapper beside the member:

=over 4

=item *

B<-S> --- stop after compiling to System/370 HLASM assembler (F<.s>).

=item *

B<-c> --- compile and assemble to an OS/360 object deck (F<.o>).

=item *

default --- compile, assemble and link to an MVS load-module member, named by
B<-o> (conventionally F<.lm>).

=item *

B<-flinker-output=xmit> --- also package the member as a TSO TRANSMIT (NETDATA,
RECFM=FB80) file I<out>F<.xmit>, ready to upload and install on MVS with
C<RECV370>; B<-flinker-output=iebcopy> instead writes the IEBCOPY unloaded-PDS
image I<out>F<.iebcopy> (e.g. to pack into a multi-member library with
L<ld370(1)> B<--pack>).

=back

The C library it links against is B<libc370>, found in the toolchain sysroot
with no B<-I>, B<-L> or B<-lc> needed.

=head1 OPTIONS

=over 4

=item B<-S>

Compile only; emit assembler (F<.s>).

=item B<-c>

Compile and assemble only; emit an object deck (F<.o>).

=item B<-o> I<file>

Place output in I<file>. With a default (link) run this is the load-module
member, and its basename also becomes the MVS member name. With a wrapper
(B<-flinker-output=>) that name must be a valid member name, which
L<ld370(1)> checks: C<-o my_prog> is refused, the underscore being no MVS
character.

With B<-c> or B<-S> and more than one source, B<-o> is refused: each source
gets its own output.

=item B<-flinker-output=>{B<xmit>|B<iebcopy>}

Additionally emit a host-to-MVS transport wrapper beside the load-module member:
B<xmit> (TSO TRANSMIT, I<out>F<.xmit>) installs with C<RECV370>; B<iebcopy>
(unloaded PDS, I<out>F<.iebcopy>) is self-describing and can be packed into a
library with L<ld370(1)> B<--pack>. Any other value is an error.

=item B<-O1>

Optimization level. B<-O1> is the validated level. B<-Os> is experimental:
it assembles across the ecosystem and passed one rexx370 test run on MVS, but
a project that uses it validates it with its own tests. B<-O2> and B<-O3> are
untested and not supported. Unit-at-a-time and strict aliasing are off by
default on this target; B<-funit-at-a-time> and B<-fstrict-aliasing> turn
them back on.

=item B<-I> I<dir>, B<-L> I<dir>, B<-l> I<name>

Add a header search directory, a library search directory, or link a library
--- as in any GCC driver.

=item B<-V>, B<--version>

Print the version and the commit it was built from, in the one line every tool
of the chain prints: C<cc370 >I<version>C< (>I<commit>C<), based on GCC 3.4.6>.

=item B<-h>, B<--help>

Show the usage and exit.

=item B<-v>

Verbose: the driver's configuration and every command it runs, as in GCC.

=item B<-dumpmachine>, B<-dumpversion>

Print the target (C<cc370>) or the product version.

=item B<-b> I<machine>, B<-V>I<version>

Refused. In GCC they choose another installed compiler; cc370 has one target and
one version.

=item B<-print-libgcc-file-name>

Print the path of the companion library F<libcc370rt.a>, which every link
pulls in.

=back

All other standard GCC driver options are accepted.

=head1 SOURCE

Trigraphs are always on, whatever B<-std> says: C<??!> is C<|> and C<??!??!> is
C<||>, as on an EBCDIC keyboard, so a string has the same value under every
dialect. Write C<?\?!> for a literal C<??!>.

C<#pragma map> and C<#pragma linkage> are recognized and have no effect; each
warns. Give an external name with C<__asm__("NAME")> on the declaration.
C<#pragma checkout>, C<nomargins> and C<nosequence> are accepted silently.

B<-pipe> is accepted and ignored: the assembler reads a file.

A B<weak reference> -- C<extern void f(void) __attribute__((weak));> -- is a
C<WXTRN>: written ahead of the first reference, an ESD entry of type WX. Left
unresolved it is 0 at run time (C<if (f) f();>), and the linkage editor's
automatic library call does not pull a definer for it. An unreferenced weak
declaration produces nothing. MVS has no weak B<definition>: one is compiled as
an ordinary definition and warns (B<-Wweak-definition>, on by default;
B<-Wno-weak-definition> switches it off). C<__CC370_WEAK__> is predefined when
the compiler supports this.

=head1 DIAGNOSTICS

MVS external names are at most 8 characters, so a longer C name is cut and two
names can become one symbol (C<codec_stream_encode> and C<codec_stream_decode>
both become C<CODEC@ST>). B<cc370> warns when that happens within one
translation unit, between definitions and references alike. Across units it
cannot see the other name: two colliding definitions get L<ld370(1)>'s
C<doubly defined> warning, a colliding reference gets nothing. An C<__asm__> name
sets the external name explicitly.

=head1 EXIT STATUS

C<0> on success, C<1> when a step failed. L<as370(1)> ends with return code
4 on a warning: the object is written and good, so the driver shows the warning
and carries on. Return code 8 and above fail the command and leave no object.

=head1 FILES

=over 4

=item F<I<prefix>/libexec/cc370/I<version>/cc1>

The compiler proper (driver-private).

=item F<I<prefix>/cc370/{include,lib}>

The libc370 sysroot (headers, F<libc.a>, startfiles).

=back
